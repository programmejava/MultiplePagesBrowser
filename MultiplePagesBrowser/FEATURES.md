# 多窗格浏览器：当前功能与使用方法

## 调整布局

工具栏第二行的布局下拉框支持原有 1 / 4 / 9 / 12 / 16 格，以及新增双栏、三栏、左大右小。

- 拖动窗格之间的蓝灰色分隔线调整宽高；“重置比例”恢复该布局的初始比例。
- 左大右小默认左侧占两份宽度、右侧占一份宽度，左侧跨两行。
- 按住窗格标题文字区域，拖到另一个窗格的标题栏上，交换两个窗格的位置。网址、登录身份、历史、缩放和运行策略跟随原浏览器实例，不重新加载。
- 双击标题或按 F11 最大化当前窗格；Esc / F11 / 还原按钮返回网格。改变布局、应用设置、打开工作区时会先还原。
- 缩小布局保留隐藏页面；同步导航仅影响当前布局可见的窗格。

## 每个窗格的工具

标题栏显示编号、网页标题，并提供刷新、声音开关、缩小、缩放复位、放大、更多菜单和关闭页面。

- 缩放范围 25%～300%；点击百分比回到 100%。网页内部更改缩放也会同步到窗格状态。
- 窄窗格自动精简标题栏，完整操作仍可从“⋯”菜单访问。
- 悬停标题可查看完整网址和最近加载状态。
- “×”关闭当前页面、停止定时刷新，保留一个空白位置，不更改整体布局。

## 工作区

1. 打开需要同时查看的页面，调整位置、比例、缩放和策略。
2. 点击“另存为”，输入名称，例如“开发监控”。
3. 后续从下拉框选择名称，点击“打开”恢复；点击“保存”用当前状态更新选中的工作区。
4. “删除”只删除保存的配置，当前打开的页面保留。

保存内容：可见窗格的网址和顺序、布局和比例、激活位置、缩放、独立声音偏好、全局声音模式、运行策略、刷新间隔及刷新暂停状态。独立模式的账号目录标识也会随顺序保存。

打开工作区会替换当前窗格，包括之前缩小布局时保留的隐藏页面。未保存的页面配置和网页表单不会保留。切换工作区会重建浏览器并重新加载保存的网址，不保留网页运行内存、历史或滚动位置。切换前如需保留当前组合，先保存工作区。

工作区显式保存，不自动覆盖；启动后可直接选择并打开。关闭窗口时，上次会话也会保存完整窗格配置，点击“上次会话”恢复。旧版本仅有布局和 URL 的会话仍可读取。

## 运行策略与定时刷新

从窗格“⋯ → 运行与定时刷新设置…”打开设置：

| 策略 | 行为 |
| --- | --- |
| 持续运行（默认） | 不因失去焦点而调用挂起或主动暂停视频，适合实时图表、聊天和监控 |
| 节能 | 非激活时按全局设置暂停视频、降低内存目标；保持网页运行，不主动挂起 |
| 暂停 | 暂停视频、隐藏浏览器并尝试挂起，停止定时刷新；显示恢复入口 |

浏览器是否允许挂起取决于当时状态，挂起失败会明确显示。网页播放器、浏览器自身的后台调度仍可能影响视频恢复和网页更新频率。

- 刷新间隔输入 1～86400 秒，0 表示关闭。
- 标题栏显示距离下次刷新的秒数。
- “暂停定时刷新”只暂停刷新，不暂停页面脚本；恢复时重新计算完整间隔。
- 页面加载期间不叠加刷新；加载结束后重新计时。空白页面不会自动刷新。
- 暂停窗格收到的新网址会暂存，恢复后加载；手动刷新、前进或后退会恢复该窗格运行。
- 定时刷新会重新加载网页，网页中未提交的输入可能丢失，建议只用于观察类页面。

## 声音控制

工具栏“声音”下拉框提供：

- 仅当前窗格发声：随激活对象切换声音。
- 每格独立控制：按照各窗格保存的声音开关发声。
- 全部静音：切换激活窗格不会解除静音。

点击窗格声音按钮会切换到“每格独立控制”，保留其他窗格当时的实际声音状态，再切换目标窗格。工具栏静音按钮切换到全局全部静音。运行策略和声音偏好独立；暂停状态下实际保持静音。

## 数据与兼容性

数据根目录：`%LocalAppData%\MultiplePagesBrowser\`。

| 文件 / 目录 | 用途 |
| --- | --- |
| workspaces.json | 命名工作区，写入临时文件后替换，保存失败会显示原因 |
| last_session.json | 上次会话，包含新配置和兼容旧版的 URL 列表 |
| settings.json、bookmarks.json | 通用设置和全局书签 |
| SharedProfile/、Profile_N/ | 共享和独立浏览器用户数据 |

Cookie 模式需要重启应用后统一生效；普通刷新不会更换已有浏览器的用户目录。工作区不复制 Cookie，也不改变全局 Cookie 模式。

旧版五种网格的索引保持不变，避免旧设置和会话变成另一种布局。设置中的间距和编号显示立即应用到已有窗格；性能开关现在只约束“节能”策略。

## 验证

仓库包含无需额外测试框架的回归执行器 `MultiplePagesBrowser.Tests`，覆盖布局和可见范围、拖动换位所用的状态操作、工作区 JSON 往返和异常数据、定时刷新状态机、最大化期间重建真实 WPF 控件，以及可选的真实 WebView2 集成测试。

真实浏览器测试仅加载本机测试网页，用户目录单独放在 `artifacts/` 下。不会使用日常登录数据。未对所有外部网站、第三方播放器、插件或长时间资源占用做兼容性/性能验证。
